# 标签功能设计讨论稿

更新日期：2026-11-11。

本文记录标签功能的目标、已确认的交互和关键设计取舍，供后续实现前讨论使用。本文不代表标签功能已经实现，也不包含正式的实施排期。

## 1. 功能目标与范围

让用户通过 Markdown 正文中的标签整理和查找笔记，同时保留文件与 Obsidian 的兼容性。

本版已确认的方向：

- 识别正文中的 `#标签`，`#` 与标签名之间不能有空格。
- 新笔记、已有笔记以及外部导入或修改的笔记使用同一套识别规则。
- 支持以 `/` 分隔的简单多级标签，例如 `#读书/心理学`。
- 侧边栏提供笔记库和标签两种视图，标签按最近使用排序。
- 支持手动添加标签。
- 提供独立的标签查询能力，点击标签后查看对应笔记。
- 暂不提供批量重命名、合并、删除正文标签等需要修改大量文件的管理功能。

以下体验建议留在后续版本，不作为本版的必要条件：

- 输入 `#` 时的标签补全、编辑器语法高亮、正文标签点击跳转。
- 所有笔记卡片上的独立标签 Chip。
- 多标签交集、排除标签、复杂查询表达式。
- YAML/frontmatter 的 `tags` 属性识别。
- 标签拖拽调整层级、自定义排序、颜色和置顶。

## 2. 侧边栏交互

### 2.1 顶部三个按钮

在现有 `Fiber` 字样下面增加一排三个小图标按钮：

| 按钮 | 类型 | 行为 |
| --- | --- | --- |
| 文件夹 | 视图切换 | 下方显示现有多库列表，保留库切换、库菜单等行为 |
| 标签 | 视图切换 | 下方显示标签列表，按最近使用排序 |
| 加号 | 操作入口 | 弹出“添加笔记库 / 添加标签”选择弹窗 |

文件夹和标签按钮需要有明确的选中状态。加号执行操作，不作为第三种列表视图。图标按钮提供“笔记库”“标签”“添加”等无障碍说明。

去掉侧边栏底部原有的“添加笔记库”按钮。热力图、全部笔记、设置入口和更新提醒继续保留，库列表或标签列表占用中间可滚动区域。

建议首次打开默认显示笔记库视图；同一次页面会话中保留切换状态。是否跨应用重启记住选中的视图，尚未确认。

### 2.2 标签列表

标签列表建议展示标签名称、层级展开按钮和笔记数量。展开按钮只控制子级显隐，点击名称进入标签笔记页。

空状态说明如何在正文中输入标签，并允许通过顶部加号添加空标签。

多级标签默认采用折叠树。同一级之间按最近使用排序；父级的最近使用时间包含其后代的使用情况，保持整棵分支位置稳定。

### 2.3 添加标签

手动添加标签只创建标签记录，不创建笔记、不向已有笔记追加文本，也不触发批量文件写入。

建议输入规则：

- 支持输入 `读书/心理学`，也接受可选的前导 `#`。
- 使用与正文识别相同的标签名校验与规范化规则。
- 同名标签已存在时定位到已有标签，不创建重复记录。
- 新建空标签显示笔记数量 `0`；点击后显示“该标签下暂无笔记”。

空标签的排序建议先使用创建时间；标签真正用于笔记后，再使用对应笔记的最近使用时间。

## 3. 独立的标签查询

### 3.1 为什么需要独立查询

已确认采用独立的标签查询能力，不把点击标签简化为向普通搜索框填入 `#标签`。

当前全文搜索使用子串匹配，无法准确表达标签身份。例如搜索 `#读书` 可能同时命中 `#读书笔记`、代码示例或 URL 片段；这些不应自动归入“读书”标签。

标签查询应读取已解析的笔记与标签关联。可以复用现有的笔记卡片、分页列表和顶栏组件，但标签查询条件、页面标题和导航状态需要独立表达。

### 3.2 查询语义建议

| 场景 | 建议行为 |
| --- | --- |
| 点击叶子标签 `读书/心理学` | 返回明确关联该标签的笔记；将来存在更深层级时，同样包含其后代 |
| 点击父标签 `读书` | 返回直接关联 `读书` 或关联任一后代标签的笔记 |
| 存在 `读书笔记` 标签 | 不计入 `读书` 分支 |
| 同一笔记包含多个后代标签 | 在结果列表和数量统计中只计一次 |
| 同一标签在正文重复出现 | 只生成一条笔记与标签关联 |
| 点击空标签 | 展示空结果，保留返回和导航能力 |

父级查询要匹配完整路径或带 `/` 边界的后代路径，不使用任意字符串前缀。SQL 条件如果使用 `LIKE`，必须正确处理通配符；更稳妥的是限定允许字符并显式构造路径边界条件。

标签笔记页建议默认按笔记修改时间倒序，使用稳定的次级排序键保证分页结果稳定。标题显示完整标签路径，并可展示去重后的笔记数。

是否在标签笔记页内增加关键词搜索或日期筛选，仍待确认，不要求首版具备完整搜索页的全部能力。

### 3.3 笔记库范围

目前尚未最终确定标签是按库隔离还是跨库共享。

建议首版使用全应用统一的标签路径：侧边栏汇总所有已添加库，同名路径合并展示，标签笔记页展示各库来源。库切换不改变标签的身份。

这个选择会影响唯一约束和查询接口，必须在实现数据库前确认。如果最终选择按库隔离，则标签唯一键需要包含 `library_id`，页面也必须显示当前库范围。

## 4. 标签识别规则

### 4.1 已确认的基础

- `#标签` 是候选标签，`# 标签` 是 Markdown 标题语法，不作为标签。
- `/` 是层级分隔符，例如 `#项目/Android/UI`。
- 标签从完整 Markdown 正文识别，不从被截断的预览文本识别。
- 新建、编辑保存、旧笔记回填、文件导入和外部同步必须使用同一个解析器。
- 新笔记的草稿可以提供临时展示，但只有成功保存的正文进入持久化标签索引。

### 4.2 建议采用的边界

“`#` 后没有空格”是基础条件，不能直接等价于全局匹配 `#\S+`。建议解析器识别 Markdown 上下文并排除：

- 围栏代码块，包括反引号和波浪号围栏，以及缩进代码块。
- 行内代码。
- Markdown 链接地址、图片地址、裸 URL 中的锚点。
- 被反斜杠转义的 `\#`。
- HTML 注释和 frontmatter 区域；本版不从 frontmatter 属性提取标签。

普通正文、列表、引用、标题文字中的有效行内标签建议可以识别。例如 `# 今日记录 #日记` 中的前一个 `#` 是标题标记，`#日记` 是候选标签。

建议允许中文和其他 Unicode 字母、数字、下划线和连字符。标点作为终止边界，避免将 `#读书，今天的心得` 识别为一个超长标签。`/` 两侧必须有有效段，`#读书//心理学`、尾部 `/` 等输入不应自动产生错误层级。

以下规则仍需确认，不能直接宣称与 Obsidian 完全一致：

- 是否允许纯数字标签，例如 `#2026`。
- `#` 前面允许哪些边界，如何处理 `C#`、`abc#tag`、连续 `##标签`。
- 全角 `＃` 是否等价于半角 `#`；建议首版只识别半角。
- 是否不区分英文大小写；建议使用稳定、与系统语言无关的规范化键，并保留显示名称。
- Unicode 规范化、最长标签长度、最大层级，以及非法路径是整项拒绝还是只识别有效部分。

示例：

| 原文 | 预期或建议 |
| --- | --- |
| `今天读完了这本书 #读书` | 识别 `读书` |
| `#读书/心理学` | 识别完整路径并产生可浏览的父级 |
| `# 读书笔记` | 不识别为标签 |
| 行内代码中的 `#读书` | 不识别 |
| 代码块中的 `#读书` | 不识别 |
| `https://example.com/#读书` | 不识别 URL 片段 |
| `\#读书` | 不识别 |
| `#读书 #读书` | 当前笔记只关联一次 |

提取结果应保留完整路径。后续若增加正文高亮或点击跳转，再扩展原文位置等信息，避免提前把编辑器渲染与索引实现绑定。

## 5. 多级标签的简单处理

以完整路径表达层级，暂不维护独立的父子关系树。例如保存 `读书/心理学` 和 `读书/小说`，界面按路径拆出 `读书` 父级。

自动生成的父级可以是虚拟节点；用户也可以手动创建或直接在正文中使用同名父级。需要区分“存在父级节点”与“正文明确关联了父级”。

父级笔记数取自身和所有后代笔记的并集，不能简单相加子级数量。展开树和父级聚合不应为每个节点单独发起一次数据库查询。

本版不通过拖拽或重命名来改变层级，用户在正文中修改路径后，下一次索引自然反映新的层级。

## 6. 最近使用排序

按最近使用排序已经确认，具体时间口径尚未最终确认。

建议首版将“含该标签笔记的最近保存/修改时间”作为使用时间的近似：

- 新笔记保存后，其标签进入最近使用位置。
- 已有笔记保存或从外部同步变更后，更新相应标签的聚合时间。
- 初次解析旧笔记时使用原笔记的修改时间，不把回填时间当作使用时间。
- 点击标签浏览不改变使用时间，避免列表在点击后跳动。
- 多级父节点取自身及后代的最大时间；同一层级按该时间倒序，时间相同时按规范化路径稳定排序。
- 没有笔记的手动标签使用创建时间作为排序后备值。

这种口径意味着修改一篇已有笔记的其他内容，也会刷新该笔记中标签的使用时间。若要求只在“新增标签”时刷新，则需要额外记录关联建立时间并定义外部修改的处理规则，复杂度更高。

## 7. 数据来源与持久化

### 7.1 文件与数据库职责

Markdown 文件是笔记内容和实际标签引用的事实来源；Room 保存可重建的查询索引。界面不能仅增加数据库关联而不修改正文，否则下次同步会覆盖该关联。

手动创建的空标签是例外：它是应用内的独立记录，不写入 Markdown。清除应用数据或重新添加文件库后，可以重新识别文件中的标签，但无法仅靠 Markdown 恢复尚未使用过的空标签。

### 7.2 建议的数据结构

由于本版包含“添加标签”，只有关联表不足以保留空标签。建议至少有：

| 数据 | 主要内容 |
| --- | --- |
| `tags` | 标签标识、规范化完整路径、显示路径、创建时间、是否手动保留 |
| `note_tags` | 笔记 URI 与标签标识的关联，建立联合唯一约束，并为标签方向查询建立索引 |
| 笔记标签索引版本 | 记录该笔记是否已经按当前规则解析，区分未处理与已处理但没有标签 |

最近使用时间和笔记计数优先由关联与笔记元数据聚合，是否增加缓存字段要根据实际查询成本决定。暂不加入必须跨表维护的计数缓存或真正的 `parent_id`。

自动提取且已无笔记引用的标签，建议从列表隐藏或清理；手动创建的标签保留为空标签。清理不能误删仍被虚拟父级聚合使用的分支。

## 8. 新笔记、旧笔记与同步

### 8.1 新笔记和应用内编辑

现有创建、导入和保存最终进入 `FileIndexer`，标签提取应接入这一公共索引链路，避免在每个 ViewModel 中重复实现。

每次索引都按已保存的完整正文重新计算该笔记的标签集合，同时移除已从正文删除的关联。笔记索引、标签关联和索引版本需要在同一数据库事务内提交。

当前 `MarkdownFileDao` 插入使用 `OnConflictStrategy.REPLACE`。如果关联表以笔记 URI 建立级联外键，替换笔记可能删除旧关联；实现时必须调整写入策略或在同一事务中完整重建关联。

### 8.2 旧笔记回填与数据库迁移

当前数据库为 v5。若标签是下一次结构变更，则增加 v5 → v6 迁移；如果实现前另有 schema 升级，需要以实际版本为准。

结构迁移只创建表、索引和初始状态，不在 Room migration 回调里遍历 SAF 文件或执行复杂 Markdown 解析。

旧笔记优先从已缓存的完整 `content_text` 分批提取标签，正文缺失或文件有变更时再读取实际文件。不要为标签迁移清空现有预览或其他索引。

需要明确的标签索引版本和待处理状态，不能把“没有关联行”等同于“尚未解析”，也不能依赖现有 20 条笔记的重建进度阈值来决定是否执行回填。小库同样必须完整处理。

回填需要能在中断后继续，并与新笔记保存和常规同步协调，避免旧正文的解析结果覆盖刚保存的新正文。可复用现有索引互斥机制，或在提交前校验内容版本。

回填未完成时，应说明标签数据正在整理，避免把暂未完成的索引显示成已经确认的空结果。后台补建不应把全库正文一次性读入内存。

### 8.3 外部修改、删除和失败

- Obsidian 等外部应用修改文件后，在现有库同步时更新标签，不承诺本版实时监听外部修改。
- 删除笔记和移除库时清理关联，并重新计算数量和排序。
- SAF 重命名可能改变 URI，必须重建或迁移关联，避免遗留失效引用。
- 文件暂不可读或授权失效时保留可用旧索引并允许重试，不把读取失败当作空正文清掉所有标签。
- 空文件、没有标签的文件也应标记为已成功解析，避免每次启动重复处理。
- 现有外部同步主要依据文件修改时间识别变化；无法可靠报告变化的文件提供方属于既有限制，必要时提供手动重建能力。

## 9. 受影响的现有模块

| 模块 | 影响 |
| --- | --- |
| `FiberDatabase`、Entity、DAO、schema 导出 | 标签表、关联表、索引状态、迁移、分页和聚合查询 |
| `FileIndexer`、`MarkdownIndexWriter`、同步规划与协调 | 公共提取、事务写入、旧数据回填、删除和 URI 变化 |
| `Sidebar`、`SidebarViewModel` | 两种列表视图、三个按钮、最近使用列表、添加标签弹窗 |
| `MainScreen`、现有笔记浏览页中的侧边栏调用 | 传递新增导航和操作回调，保持各入口行为一致 |
| `FiberNavGraph` | 独立标签笔记路由；对包含 `/`、中文等内容的路径正确编码 |
| 新标签笔记页与查询状态 | 复用卡片和 Paging，独立维护标签条件与页面状态 |
| 依赖注入 | 提供标签查询和索引所需依赖 |

普通全文搜索、编辑器输入、现有卡片不必为了首版标签功能同时增加完整的标签交互。跨库打开笔记时，需要沿用或补齐正确的库上下文，保证附件加载和后续保存目标正确。

## 10. 关键验证场景

- 同一正文通过新建、保存、导入和旧数据回填得到一致标签集合。
- 代码、URL、转义、标题、多语言文本和标点边界不会造成明显误识别。
- 父级查询包含后代但排除名称相似的其他标签，列表和计数均去重。
- 手动空标签保存后仍存在，同名添加不重复，点击空标签有明确结果。
- 标签最近使用排序符合最终确认的时间口径，回填不会把所有旧标签变成“刚刚使用”。
- v5 升级后保留笔记和现有索引，小库、空库、多库和回填中断均可恢复。
- 编辑移除标签、外部修改、笔记删除、移除库和 URI 变化不会遗留关联。
- 写入失败和文件读取失败不会把有效标签静默清空。
- 大库分页不加载全部正文，也不按每张卡片或每个树节点单独查询。

## 11. 实现前仍需确认

1. 标签是全应用共享路径，还是按笔记库隔离；首版是否需要库范围筛选。
2. 最近使用是否接受按“含标签笔记的修改时间”近似，而不是精确记录标签新增时间。
3. 完整字符边界、纯数字、大小写、Unicode 与非法层级的识别规则。
4. 标签笔记页是否默认包含后代，以及是否需要关键词或日期筛选。
5. 多级列表默认展开状态、是否跨启动记住侧边栏视图。
6. 空标签的保留和排序规则，以及其仅存于应用内的恢复边界。

以上未确认项在本文中的具体处理均为建议，不视为已确认需求。
