# 标签功能设计与实现

更新日期：2026-11-12。

本文记录标签功能的目标、已确认的交互和关键设计取舍。首版功能已按本文实现，具体实现约定及验证方式见第 12 节。

## 1. 功能目标与范围

让用户通过 Markdown 正文中的标签整理和查找笔记，同时保留文件与 Obsidian 的兼容性。

本版已确认的方向：

- 识别正文中的 `#标签`，`#` 与标签名之间不能有空格。
- 新笔记、已有笔记以及外部导入或修改的笔记使用同一套识别规则。
- 支持以 `/` 分隔的简单多级标签，例如 `#读书/心理学`。
- 侧边栏提供笔记库和标签两种视图，按关联笔记的最近修改时间排序标签。
- 跨应用重启只记住上次打开的是笔记库还是标签视图，不记住多级标签的折叠状态。
- 支持手动添加标签，并允许删除尚无笔记使用的手动空标签；这类删除仅修改数据库。
- 提供独立的标签查询能力，点击标签后查看对应笔记。
- 点击父标签包含全部后代的笔记，结果和数量按笔记去重。
- 标签跨库统一，不属于某个特定笔记库；切换当前库不改变标签列表、统计、排序或查询结果。
- 识别纯数字标签；英文大小写不同视为同一个标签。
- 标题行只排除行首标题标记，继续识别标题文字中的标签；非法层级取最长有效前缀。
- 编辑器工具栏新增标签按钮，点击直接输入半角 `#`，本版不提供标签选择器。
- 旧笔记整理期间显示带小进度条的非模态浮窗，主界面仍可操作。
- 暂不提供批量重命名、合并、删除正文标签等需要修改大量文件的管理功能。

以下体验本版暂不提供：

- 输入 `#` 时的标签补全、编辑器语法高亮、正文标签点击跳转。
- 所有笔记卡片上的独立标签 Chip。
- 多标签交集、排除标签、复杂查询表达式。
- 标签笔记页内的关键词搜索和日期筛选。
- YAML/frontmatter 的 `tags` 属性识别。
- 标签拖拽调整层级、自定义排序、颜色和置顶。

## 2. 侧边栏交互

### 2.1 顶部三个按钮

在现有 `Fiber` 字样下面增加一排三个小图标按钮：

| 按钮 | 类型 | 行为 |
| --- | --- | --- |
| 文件夹 | 视图切换 | 下方显示现有多库列表，保留库切换、库菜单等行为 |
| 标签 | 视图切换 | 下方显示所有已添加库的统一标签列表，按最近使用排序，不随当前库切换 |
| 加号 | 操作入口 | 弹出“添加笔记库 / 添加标签”选择弹窗 |

文件夹和标签按钮需要有明确的选中状态。加号执行操作，不作为第三种列表视图。图标按钮提供“笔记库”“标签”“添加”等无障碍说明。

去掉侧边栏底部原有的“添加笔记库”按钮。热力图、全部笔记、设置入口和更新提醒继续保留，库列表或标签列表占用中间可滚动区域。

首次打开且没有历史选择时默认显示笔记库视图。之后跨应用重启记住上一次打开的是笔记库还是标签视图，只持久化这一视图选择，不保存标签树的折叠状态。

### 2.2 标签列表

标签列表建议展示标签名称、层级展开按钮和笔记数量。展开按钮只控制子级显隐，点击名称进入标签笔记页。

空状态说明如何在正文中输入标签，并允许通过顶部加号添加空标签。

多级标签默认采用折叠树。同一级之间按最近使用排序；父级的最近使用时间包含其后代的使用情况，保持整棵分支位置稳定。

不要求恢复上一次的展开或折叠状态，也不额外保存本次会话的展开记录；视图重建时可以回到默认折叠状态。

### 2.3 添加标签

手动添加标签只创建标签记录，不创建笔记、不向已有笔记追加文本，也不触发批量文件写入。

手动创建的标签属于全应用，不绑定创建时选中的库；不同库识别出的同名标签与该记录共用同一个标签身份。

建议输入规则：

- 支持输入 `读书/心理学`，也接受可选的前导 `#`。
- 使用与正文识别相同的字符和规范化规则；手动输入非法层级时提示有效前缀或校正格式，不静默创建用户未确认的路径。
- 同名标签已存在时复用其身份并定位，不创建重复记录；包括已有自动标签和虚拟父级，都标记为手动保留。
- 新建空标签显示笔记数量 `0`；点击后显示“该标签下暂无笔记”。

已确认：手动空标签保留，尚未被笔记使用时按创建时间排序；有笔记关联后，按关联笔记的最近修改时间排序。允许删除手动空标签，操作只修改数据库，不删除笔记或修改 Markdown 文件。空标签需同时没有直接和后代笔记引用；虚拟节点与存在关联笔记的标签本版不提供删除操作。

删除空标签不能级联删除其子标签记录。若该路径仍是其他手动空标签的父级，只取消该节点的手动保留状态，继续显示为不可删除的虚拟父节点。

### 2.4 编辑器工具栏标签按钮

已确认：本版在编辑器工具栏新增标签图标按钮，提供明确的“标签”无障碍说明。这是本版需求，不与输入 `#` 自动补全一起后置。

已确认：点击直接在当前光标位置插入半角 `#`（U+0023），光标移动到 `#` 后，便于继续输入标签。不会弹出已有标签选择器，也不提供补全。该按钮主要解决手机键盘上的全角 `＃` 与有效半角 `#` 外观相近、容易误输的问题。

复用现有 `EditorOperations.replace` 和 `EditorSession` 的普通插入行为：若有选区则以 `#` 替换选区，插入是可撤销的一步操作，不夺取输入焦点。不添加标题按钮使用的尾随空格，也不自动插入标签名称或更改为标题格式；用户负责标签前的分隔空白，识别规则保持一致。

该需求针对编辑器工具栏，不扩展快速笔记输入栏。修改遵循当前笔记的草稿、撤销和保存流程，保存成功后再更新标签索引，不修改其他笔记文件。后续阶段可以再加入标签选择器与补全。

## 3. 独立的标签查询

### 3.1 为什么需要独立查询

已确认采用独立的标签查询能力，不把点击标签简化为向普通搜索框填入 `#标签`。

当前全文搜索使用子串匹配，无法准确表达标签身份。例如搜索 `#读书` 可能同时命中 `#读书笔记`、代码示例或 URL 片段；这些不应自动归入“读书”标签。

标签查询应读取已解析的笔记与标签关联。可以复用现有的笔记卡片、分页列表和顶栏组件，但标签查询条件、页面标题和导航状态需要独立表达。

`note_tags` 只保存正文明确出现的完整标签路径，不把自动生成的祖先伪装成直接关联。例如正文只有 `#读书/心理学` 时，仅关联 `读书/心理学`；查询 `读书` 时通过后代路径匹配包含该笔记。是否虚拟只影响节点来源与操作，不决定父级查询是否包含后代。

### 3.2 已确认的查询语义

| 场景 | 行为 |
| --- | --- |
| 点击叶子标签 `读书/心理学` | 返回明确关联该标签的笔记；将来存在更深层级时，同样包含其后代 |
| 点击父标签 `读书` | 返回直接关联 `读书` 或关联任一后代标签的笔记 |
| 存在 `读书笔记` 标签 | 不计入 `读书` 分支 |
| 同一笔记包含多个后代标签 | 在结果列表和数量统计中只计一次 |
| 同一标签在正文重复出现 | 只生成一条笔记与标签关联 |
| 点击空标签 | 展示空结果，保留返回和导航能力 |

父级查询要匹配完整路径或带 `/` 边界的后代路径，不使用任意字符串前缀。SQL 条件如果使用 `LIKE`，必须转义路径中的 `_` 等通配符，再追加 `/` 边界；也可以使用等值匹配和显式路径前缀判断。不能仅凭标签允许字符有限就省略通配符处理。

标签笔记页展示完整标签路径、去重后的笔记数量，以及按笔记修改时间倒序的笔记列表。使用稳定的次级排序键保证分页结果稳定。

已确认首版不在标签笔记页内加入关键词搜索或日期筛选。

### 3.3 笔记库范围

已确认：标签是跨库的，不受特定库或当前激活库影响。

具体约束：

- 使用全应用统一的标签路径；大小写不同的同名路径在所有库中只对应一个标签。
- 侧边栏汇总所有已添加库的标签，标签计数和最近使用时间均跨库聚合。
- 标签笔记页查询所有已添加库中关联该标签的笔记，并展示笔记所属库，便于区分来源。
- 标签列表、计数、排序和查询不能依赖当前激活库；即使没有激活库，只要仍有已添加库和有效索引，也能浏览标签。
- 本版标签查询不加入单库范围筛选。
- 手动创建的空标签同样全局保存。移除或切换某个库，不删除全局手动标签。
- 移除库时，只清理该库笔记的标签关联并重算全局聚合；其他库的同名标签和关联继续有效。
- 从标签页打开笔记时，文件读取、附件解析和保存使用该笔记自身的库上下文；即使现有打开逻辑切换激活库，返回后的标签查询范围也保持全局。

数据库唯一约束使用全局规范化路径，不包含 `library_id`；标签与库的关系通过笔记关联推导。

## 4. 标签识别规则

### 4.1 已确认的基础

- `#标签` 是候选标签，`# 标签` 是 Markdown 标题语法，不作为标签。
- `/` 是层级分隔符，例如 `#项目/Android/UI`。
- 标签从完整 Markdown 正文识别，不从被截断的预览文本识别。
- 新建、编辑保存、旧笔记回填、文件导入和外部同步必须使用同一个解析器。
- 新笔记的草稿可以提供临时展示，但只有成功保存的正文进入持久化标签索引。

### 4.2 已确认的识别边界

“`#` 后没有空格”是基础条件，不能直接等价于全局匹配 `#\S+`。解析器识别 Markdown 上下文并排除：

- 围栏代码块，包括反引号和波浪号围栏，以及缩进代码块。
- 行内代码。
- Markdown 链接地址、图片地址、裸 URL 中的锚点。
- 被反斜杠转义的 `\#`。
- HTML 注释和 frontmatter 区域；本版不从 frontmatter 属性提取标签。

普通正文、列表、引用、标题文字中的有效行内标签可以识别。标题判断只识别行首合法的标题 `#` 组（考虑 Markdown 允许的缩进、标题级数和组后的空白），排除对应标记后，继续扫描标题正文，不能因为整行是标题就直接跳过。

例如原文 `# 今日记录 #日记` 只识别 `日记`；`## 今日记录 #日记` 也应得到相同标签。若原文实际是 `\# 今日记录 #日记`，第一个 `#` 因转义而忽略，后面的 `#日记` 仍需识别。列表或引用中的标题遵循对应 Markdown 结构；标题结尾仅作为闭合标记的 `#` 组不产生标签。

允许中文和其他 Unicode 字母、数字、下划线和连字符，`/` 作为层级分隔符。除这些允许字符以外的标点作为终止边界，避免将 `#读书，今天的心得` 识别为一个超长标签。

已确认非法层级保留最长的有效路径前缀：逐段读取，每段必须非空，遇到空段或末尾 `/` 时退回上一个有效段的结尾。`#读书//心理学` 和 `#读书/` 都只识别 `读书`；`#项目/Android//UI` 只识别 `项目/Android`。不把断点后剩余文本重新拼接，也不生成空段或重复 `/` 的路径。若第一个段就无效，例如 `#/心理学`，则没有可用前缀，不生成标签。该处理只影响识别结果，不重写 Markdown 原文。手动添加弹窗保持格式提示，避免静默截断后创建与输入意图不同的标签。

其他已确认规则：

- 允许纯数字标签，例如 `#2026`；多级路径中也允许数字段。
- 不识别 `C#`、`abc#tag` 和连续 `##标签`，避免将单词内部或重复的 `#` 当作标签起点。
- 只识别半角 `#`，全角 `＃` 不等价。
- 英文大小写不区分，`#Android` 和 `#android` 视为同一个标签；多级路径的每一段都遵循该规则。

使用与系统语言无关的规范化键。显示名称默认保留首次记录的拼写，后续大小写变体不产生新标签或反复修改展示。Unicode 规范化方式、最长标签长度和层级保护作为实现细节保持统一。

本版采用上述规则，不宣称完全复刻 Obsidian 的全部标签语法。

示例：

| 原文 | 预期 |
| --- | --- |
| `今天读完了这本书 #读书` | 识别 `读书` |
| `#读书/心理学` | 识别完整路径并产生可浏览的父级 |
| `# 读书笔记` | 不识别为标签 |
| `# 今日记录 #日记`、`## 今日记录 #日记` | 排除行首标题标记，但识别行内 `日记` |
| `\# 今日记录 #日记` | 忽略被转义的第一个 `#`，仍识别 `日记` |
| 行内代码中的 `#读书` | 不识别 |
| 代码块中的 `#读书` | 不识别 |
| `https://example.com/#读书` | 不识别 URL 片段 |
| `\#读书` | 不识别 |
| `#读书 #读书` | 当前笔记只关联一次 |
| `#2026` | 识别纯数字标签 `2026` |
| `#Android #android` | 当前笔记只关联一个标签，跨库也合并为同一个标签 |
| `#项目/Android #项目/android` | 大小写不同的同一路径只关联一次 |
| `#读书，今天的心得` | 只识别 `读书`，逗号终止标签 |
| `abc#tag`、`##标签`、`＃标签` | 不识别 |
| `#读书//心理学`、`#读书/` | 保留有效前缀 `读书` |
| `#项目/Android//UI`、`#项目/Android/` | 保留有效前缀 `项目/Android` |
| `#/心理学` | 无有效前缀，不生成标签 |

提取结果应保留完整路径。后续若增加正文高亮或点击跳转，再扩展原文位置等信息，避免提前把编辑器渲染与索引实现绑定。

## 5. 多级标签的简单处理

以完整路径表达层级，不引入独立树表或 `parent_id`。界面和查询按路径补齐父级；虚拟父级是否实体化存入 `tags` 不影响标签身份和查询语义。建议首版继续从路径生成虚拟父级，不为每个祖先持久化一条独立记录。

需要区分三个事实：节点是否手动创建并保留、正文是否直接引用它、节点是否仅为容纳后代而存在。这三个事实不能由一个持久化布尔值完整替代。

查询投影复用计划中的 `is_manual`（手动保留字段）和 `note_tags`，输出以下状态；这些名称是拟定的设计字段，不代表当前代码已有：

```text
has_direct_reference = EXISTS(note_tags 中直接关联该完整路径的有效笔记)
is_explicit = is_manual OR has_direct_reference
is_virtual = NOT is_explicit AND has_visible_descendant
```

生成的虚拟父级没有 `tags` 实体时，`is_manual` 视为 false，查询或组装列表投影仍返回 `is_virtual = true`。父级本身写入正文或手动添加后，对应路径拥有实体记录，但不改变全局路径身份。

| 来源状态 | `is_manual` | 直接引用 | 查询得到的节点状态 |
| --- | --- | --- | --- |
| 仅有 `读书/心理学`，父级没有直接引用 | false | 无 | `读书` 是虚拟节点 |
| 某篇正文又出现 `#读书` | false | 有 | `读书` 是 explicit 节点，但并非手动保留 |
| 手动添加同名 `读书` | true | 可有可无 | `读书` 是 explicit 节点，去重或复用已有记录 |
| 删除最后一条父级直接引用，仍有子标签 | false | 无 | 自动回到虚拟节点 |
| 手动空父级被删除，仍有手动空子标签 | false | 无 | 取消手动保留后回到虚拟节点，子标签保留 |

不建议仅持久化 `is_explicit` 或 `is_virtual` 后就用它判断来源：手动创建与正文直接引用都可能是 explicit，但失去引用后的保留策略不同。首版保留 `is_manual` 为事实字段，在查询投影计算上述状态，减少同步、回填和删除时额外维护派生状态的风险。若以后因性能需要缓存虚拟状态，应在同一事务重算，不能将其作为直接引用的替代依据。

虚拟节点不提供用户删除入口。删除候选必须是手动保留的 explicit 节点，且整个分支没有有效笔记引用；不能仅凭 `is_explicit = true` 就允许删除。有可见后代但无笔记引用时，只取消该节点的手动保留，不能级联删除后代。失去直接引用的自动父级若仍有后代，应继续作为虚拟节点显示。

父级笔记数取自身和所有后代笔记的并集，不能简单相加子级数量。展开树和父级聚合不应为每个节点单独发起一次数据库查询。

本版不通过拖拽或重命名来改变层级，用户在正文中修改路径后，下一次索引自然反映新的层级。

## 6. 最近使用排序

已确认按“含该标签笔记的最近修改时间”排序，取所有关联笔记修改时间的最大值：

- 新笔记保存后，其标签进入最近使用位置。
- 已有笔记保存或从外部同步变更后，更新相应标签的聚合时间。
- 初次解析旧笔记时使用原笔记的修改时间，不把回填时间当作使用时间。
- 点击标签浏览不改变使用时间，避免列表在点击后跳动。
- 多级父节点取自身及后代的最大时间；同一层级按该时间倒序，时间相同时按规范化路径稳定排序。
- 聚合覆盖所有已添加库，切换当前库不改变标签顺序。
- 没有笔记的手动标签使用创建时间作为排序后备值。

即使只修改笔记的其他内容，也会刷新该笔记中标签的排序时间。这是本版已接受的行为，不额外记录标签首次插入或新增关联的时间用于排序。

## 7. 数据来源与持久化

### 7.1 文件与数据库职责

Markdown 文件是笔记内容和实际标签引用的事实来源；Room 保存可重建的查询索引。界面不能仅增加数据库关联而不修改正文，否则下次同步会覆盖该关联。

手动创建的空标签是例外：它是应用内的全局独立记录，不写入 Markdown，也不隶属于创建时的当前库。移除或重新添加某个文件库不会删除这些手动标签。清除应用数据后，可以从重新导入的 Markdown 识别实际使用过的标签，但无法仅靠文件恢复尚未使用过的空标签及其手动保留状态。

### 7.2 建议的数据结构

由于本版包含“添加标签”，只有关联表不足以保留空标签。建议至少有：

| 数据 | 主要内容 |
| --- | --- |
| `tags` | 全局标签标识、全局唯一的规范化完整路径、显示路径、创建时间、`is_manual` 手动保留字段；不设所属库字段 |
| `note_tags` | 笔记 URI 与标签标识的关联，建立联合唯一约束，并为标签方向查询建立索引 |
| `markdown_files.tag_index_version` | 记录该笔记的已保存正文按哪个标签解析规则成功建立索引，初始值为 0 |
| 标签列表查询投影 | 根据手动保留、直接引用与后代存在情况计算 `has_direct_reference`、`is_explicit`、`is_virtual`，不以派生状态替代事实字段 |

最近使用时间和笔记计数优先由关联与笔记元数据聚合，是否增加缓存字段要根据实际查询成本决定。暂不加入必须跨表维护的计数缓存或真正的 `parent_id`。

已确认：自动提取且整个分支已无笔记引用、也无手动保留后代的标签从列表隐藏；手动创建的标签保留为空标签，允许用户删除未被使用的手动空标签。自动父级失去直接引用后，若仍有可见后代，应退回虚拟节点而非隐藏整条分支。底层可以清理无用自动记录，但不能误删仍被虚拟父级聚合使用的分支或其他库的有效关联。

是否无引用必须检查所有库的关联，不能仅因当前库没有使用该标签就隐藏或删除它。

## 8. 新笔记、旧笔记与同步

### 8.1 新笔记和应用内编辑

现有创建、导入和保存最终进入 `FileIndexer`，标签提取应接入这一公共索引链路，避免在每个 ViewModel 中重复实现。

每次索引都按已保存的完整正文重新计算该笔记的标签集合，同时移除已从正文删除的关联。笔记索引、标签关联和索引版本需要在同一数据库事务内提交。

当前 `MarkdownFileDao` 插入使用 `OnConflictStrategy.REPLACE`。如果关联表以笔记 URI 建立级联外键，替换笔记可能删除旧关联；实现时必须调整写入策略或在同一事务中完整重建关联。

### 8.2 旧笔记回填与数据库迁移

当前数据库为 v5。若标签是下一次结构变更，则增加 v5 → v6 迁移；如果实现前另有 schema 升级，需要以实际版本为准。

结构迁移只创建表、索引和初始状态，不在 Room migration 回调里遍历 SAF 文件或执行复杂 Markdown 解析。

旧笔记优先从已缓存的完整 `content_text` 分批提取标签，正文缺失或文件有变更时再读取实际文件。不要为标签迁移清空现有预览或其他索引。

需要明确的标签索引版本和待处理状态，不能把“没有关联行”等同于“尚未解析”，也不能依赖现有 20 条笔记的重建进度阈值来决定是否执行回填。小库同样必须完整处理。

回填需要能在中断后继续，并与新笔记保存和常规同步协调，避免旧正文的解析结果覆盖刚保存的新正文。具体版本语义与进度交互见 8.4、8.5。

### 8.3 外部修改、删除和失败

- Obsidian 等外部应用修改文件后，在现有库同步时更新标签，不承诺本版实时监听外部修改。
- 删除笔记和移除库时清理相应关联，并跨库重新计算数量和排序；保留其他库的关联及全局手动标签。
- SAF 重命名可能改变 URI。沿用现有 URI 主键和同步链路处理，不引入稳定笔记 ID、重命名映射表或文件指纹系统；具体约束见 8.6。
- 文件暂不可读或授权失效时保留可用旧索引并允许重试，不把读取失败当作空正文清掉所有标签。
- 空文件、没有标签的文件也应标记为已成功解析，避免每次启动重复处理。
- 现有外部同步主要依据文件修改时间识别变化；无法可靠报告变化的文件提供方属于既有限制，必要时提供手动重建能力。

### 8.4 笔记标签索引版本

在现有 `markdown_files` 增加 `tag_index_version INTEGER NOT NULL DEFAULT 0`，标签解析器对应一个代码常量，例如 `CURRENT_TAG_INDEX_VERSION = 1`。

| 字段值或条件 | 语义 |
| --- | --- |
| `0` | 尚未成功建立标签索引，或已明确标记需要重新处理 |
| 小于当前规则版本 | 待回填或规则升级后待重建 |
| 等于当前规则版本 | 数据库缓存的这份正文已按当前规则完整解析并提交关联，即使结果为空 |
| 大于当前规则版本 | 通常表示运行旧代码，不据此自动降级覆盖数据，版本回退另行处理 |

该字段是解析规则版本，不是笔记修订号，也不是 Room schema 版本。Room 的 v6 与标签解析器的 v1 没有数值对应关系。修改解析规则且影响结果时才提高代码常量；修改正文仍必须重新解析，不能因为 `tag_index_version` 已是当前值就跳过保存或外部变更后的标签更新。

写入约束：

- 首次结构迁移为已有笔记默认填 0，按 `tag_index_version < CURRENT_TAG_INDEX_VERSION` 分批获取待处理记录；后续解析规则升级保留旧版本值即可，不必全部重置为 0。不要把所有正文一次性加载进内存。
- 新建、保存和外部同步成功时，正文缓存、直接标签关联与当前版本在同一事务提交。正文被单独更新而标签尚未成功处理时，版本必须标为 0，不能沿用旧的成功标记。
- 正文没有标签或确实为空，也要提交当前版本，避免永久重复回填。
- 读取或解析失败不视为无标签成功。保留有效旧关联，让该记录保持待处理或进入既有同步重试路径，不把失败时间写成笔记修改时间。
- 标签回填不能只提升版本却漏写关联；事务回滚时，关联与版本一起回滚。
- 运行规则版本升级后，旧关联可以暂时用于展示，但界面说明数据仍在整理，后台完成后再替换；不预先清空全库标签。

不为回填额外增加笔记内容修订字段：复用 `FileIndexer` 的索引互斥锁，按单篇或小批次覆盖“读取数据库当前正文 → 解析 → 事务提交”的过程。库扫描结果不得携带旧正文越过这个锁覆盖新保存内容；如果将来为了性能改为锁外解析，则提交前必须校验读到的正文快照仍然有效，变化时丢弃旧结果并重试。

版本标记只保证“已缓存的正文是否解析成功”，不能证明外部文件没有变化；外部新内容是否需要读取，仍由现有文件同步负责。中断后重新查询低版本记录继续，不需要另存回填游标。

### 8.5 非阻塞的回填进度浮窗

已确认：整理未完成时显示一个小型进度浮窗，包含“标签数据正在整理”和线性小进度条。可用时展示成功处理数与总数；任务准备阶段可以先显示不定进度。

这里的“弹窗”采用非模态呈现：放在应用主界面之上的小浮层，或配置为不获取焦点的 Popup，不使用带遮罩、拦截外部点击的 `AlertDialog`/模态 `Dialog`。主界面、侧边栏、编辑、保存和导航继续可操作，不替换当前列表，也不让主界面切到现有的全屏同步进度状态。

- 进度状态由持有任务的协调层通过 `StateFlow` 等状态流提供，不仅依赖一次性事件；浮窗重组、切页后仍反映同一任务。
- 处理在后台线程分批执行，索引锁和事务只覆盖单篇或小批次，批次之间释放，不在整个回填期间占锁；避免用户保存虽然能点击却被全库任务长时间排队。
- 仅在关联和版本成功提交后计入完成进度。并发保存顺便完成待回填记录时，也按实际待处理状态更新进度，不能重复计数或超过 100%。
- 全部成功后浮窗自动消失；部分失败保留待处理记录，并显示未完成与重试状态，不能将失败计作成功后直接显示全部完成。
- 任务取消、应用退出后，已提交记录保持当前版本；下次继续低版本记录，不从头清空重做。
- 回填期间标签列表和结果可以增量出现，但要说明仍在整理，不能把尚未处理的部分显示为最终的“没有标签/没有笔记”。

### 8.6 不引入稳定笔记 ID 的 SAF 重命名处理

当前实现是 `FileRepositoryImpl.renameFile` 在 SAF 重命名后先调用 `deleteFile(oldUri)`，再调用 `insertFile(newUri)`。两次索引操作各自加锁；新索引失败时旧索引已被删除，而且返回的插入结果没有影响重命名成功返回。这不能直接套用到新增标签关联后继续使用。

本版沿用 URI 主键，在现有 `FileRepositoryImpl`、`FileIndexer` 和 Room DAO 内收拢重命名处理即可，不增加永久笔记身份或新的恢复子系统：

1. 应用内重命名先取得现有索引互斥锁，再读取旧笔记索引快照、所属库以及已缓存的直接标签关联；SAF 操作和索引切换都在这次单文件锁范围内协调。不要在 SAF 操作前或准备新索引前删除旧记录；索引库已知时不能误用当前激活库代替原所属库。
2. 重命名、常规索引和回填复用同一把锁，避免同步在操作中途把新旧 URI 当作两篇独立笔记处理。不要在已持锁时再调用会重复获取同一把锁的公开 delete/insert 方法，应在现有索引写入层完成组合操作。
3. 以 `DocumentsContract.renameDocument` 实际返回的 URI 为准，不自行推算路径。返回 URI 与旧 URI 相同时，仅更新元数据和必要的关联，不先删除记录。
4. 返回不同 URI 时，先准备新 URI 的索引。纯重命名不改变正文，已有可信的已保存索引时，可以迁移原正文缓存、直接关联和原 `tag_index_version`，只更新 URI、名称等文件身份元数据，无须为 URI 迁移强制重读全部正文。旧版本仍保持待回填状态，不能直接提升为当前版本。若同时需要刷新内容，则读取成功后重新解析；读取失败不能当作空正文，也不能单纯将版本置 0 来表达“文件尚未读取确认”，因为缓存回填无法完成这种确认。已发现内容可能变更时，保留旧内容对应的同步元数据并通过既有同步路径重读，不能把旧正文标成已同步的新内容；没有可信旧索引且新正文读取失败时，不提交切换，进入下述失败恢复路径。
5. 在一个 Room 事务内先建立新 URI 的笔记记录和标签关联，再删除旧 URI 的关联与笔记记录。父笔记必须先于其关联插入，旧关联删除不能影响新关联；不要直接更新被外键引用的主键，也不能依赖两次独立的 delete/insert 实现原子性。标签全局记录和手动保留状态不因 URI 改变而重建。
6. 事务成功后刷新列表。只要 SAF 重命名成功，编辑器就必须将 `currentFileUri` 更新为实际返回 URI，数据库提交失败也不能继续使用旧 URI。后续保存和附件解析使用新 URI；迁移的正文必须来自已保存内容，不能把未保存草稿写进文件索引。

现有 `MarkdownContentReader` 将读取异常吞成空串，保存索引路径也有吞掉错误的情况。满足以上约束需要调整既有返回与错误传播，区分“成功读到空文件”和“读取失败”，不是另建一套文件身份机制。

失败边界：SAF 文件操作与 SQLite 事务无法构成同一个事务。文件重命名已经成功、但数据库事务失败时，不能尝试继续保存到旧 URI，也不能笼统返回“文件没有改名”。在已知新 URI 的情况下仍要让编辑器使用新 URI，并显式提示索引待修复，通过原库的既有同步入口进行恢复；需要给现有结果或刷新路径表达这一部分成功状态。数据库事务回滚保留原索引，下一次库同步重新扫描后按真实文件状态修复。进程恰好在两者之间退出，也靠下次同步修复，因此本方案保证的是正常路径中的数据库原子切换和异常后的最终一致，不能承诺跨文件系统和数据库的绝对原子性。

外部应用重命名没有可信的新旧对应关系：沿用现有扫描，将其视为“发现新 URI + 旧 URI 消失”。本轮新增记录成功建立正文与关联后，再清理消失的旧记录；存在新增文件读取失败时暂缓本轮旧记录清理，避免旧索引先丢失。每批正文、关联和版本必须原子提交，但不要求把全库正文放进一个大事务；同步完成前不因批次间的暂时零引用而提前清理全局标签。原名与内容相同都不足以证明是同一文件，因此不增加模糊匹配。

## 10. 关键验证场景

- 同一正文通过新建、保存、导入和旧数据回填得到一致标签集合。
- 代码、URL、转义、多语言文本和标点边界不会造成明显误识别；标题只跳过行首标记，`# 今日记录 #日记` 与转义行首示例仍识别行内 `日记`。
- `#读书//心理学`、`#读书/` 取有效前缀 `读书`；更深层级保留最长有效路径，首段无效时不生成标签，也不改写原文。
- 纯数字标签能识别；大小写变体在单篇笔记、多级路径及跨库查询中均合并，显示拼写保持稳定。
- 父级查询包含后代但排除名称相似的其他标签，列表和计数均去重。
- 两个库中的同名标签合并为一项，计数、最近使用和查询结果覆盖两个库；切换当前库不改变这些结果。
- 无激活库但有已添加库时仍能查询标签；跨库打开笔记再返回时保留原标签条件和全局范围。
- 移除其中一个库只减少该库的关联，其他库同名标签的笔记仍可查询，手动空标签仍保留。
- 手动空标签保存后仍存在，同名添加不重复，点击空标签有明确结果；删除空标签不修改笔记文件或子标签。
- 仅有子级引用时父级是虚拟节点，正文直接引用或手动创建后变为 explicit；直接引用移除后，按手动保留和可见后代重新判断，不能生成假的父级 `note_tags`。
- 自动节点在全部库都没有引用且没有可见后代时隐藏，手动空标签在用户删除前保留；虚拟父级不可删除，删除手动空父级不删除后代。
- 修改含标签笔记会更新排序，点击浏览不更新；回填使用原修改时间，不把所有旧标签变成“刚刚使用”。
- 重启后只恢复上次选中的标签或笔记库视图，不恢复标签树折叠状态。
- 编辑器标签按钮仅插入半角 `#`，有选区时替换选区，光标在其后，支持撤销与保存；不附加空格、不打开选择器，不能误插入全角 `＃`。
- v5 升级后保留笔记和现有索引，小库、空库、多库和回填中断均可恢复。
- 无标签和空正文成功解析后版本同样提升；解析失败不提升，规则升级可继续回填，已有当前版本的笔记修改后仍重新解析。
- 回填期间的小进度浮窗不阻断导航、编辑和保存；并发保存不被旧回填覆盖，完成数不重复累计，失败保留重试状态。
- 编辑移除标签、外部修改、笔记删除、移除库和 URI 变化不会遗留关联。
- SAF 返回相同或不同 URI 均正确处理；重命名后的正文、直接关联和版本一起迁移。数据库失败保留旧索引，编辑器仍切换到实际新 URI，后续同步可修复。
- 写入失败和文件读取失败不会把有效标签静默清空。
- 大库分页不加载全部正文，也不按每张卡片或每个树节点单独查询。

## 11. 已确认决策与设计约束

2026-11-12 的确认结果如下，原先的问题不再保留为待定项：

| 决策点 | 已确认结果 |
| --- | --- |
| 跨库范围 | 全局共享，同名标签合并，所有聚合与查询不受当前库影响 |
| 最近使用 | 按关联笔记修改时间，点击标签不更新 |
| 父级查询 | 包含所有后代，按笔记去重 |
| 标签笔记页 | 名称、数量、修改时间倒序列表，关键词和日期筛选后置 |
| 数字与大小写 | 识别纯数字，英文大小写不同视为同一个标签 |
| 识别边界 | 半角 `#`，排除代码/地址/转义/frontmatter，标题文字继续扫描，标点终止，非法层级取有效前缀 |
| 侧边栏记忆 | 只记住上次选中标签还是笔记库，不保存折叠状态 |
| 空标签与虚拟父级 | 手动空标签保留并可删除；虚拟父级不可删除，无引用且无可见后代的自动节点隐藏 |
| 本版展示入口 | 侧边栏、标签笔记页，以及新增的编辑器工具栏标签按钮 |
| 编辑器按钮 | 直接插入半角 `#`，复用普通编辑行为，不打开选择器或补全 |
| 回填进度 | 非模态小浮窗与进度条，整理未完成有状态提示，主界面可继续操作 |
| 后置体验 | 卡片 Chip、正文标签点击、输入 `#` 自动补全 |

本文建议的技术表达是：`is_manual` 保存手动保留事实，直接引用由 `note_tags` 表达，`is_virtual` / `is_explicit` 在查询投影中计算；`tag_index_version` 单独标记每篇已缓存正文的解析规则版本。URI 变化沿用现有主键、锁、事务和同步入口处理，不增加稳定笔记 ID 或重命名映射系统。

Unicode 规范化方式与长度保护等统一实现约定见下节。

## 12. 首版实现记录

2026-11-12 已完成以下实现：

- `TagParser` 统一处理新建、保存、导入、同步与回填的已保存正文。使用 CommonMark 结构排除代码及地址上下文，并单独保留转义与 frontmatter 边界；标题正文继续扫描标签。
- 字符规范采用 Unicode NFC，规范化键使用 `Locale.ROOT` 小写，保留首次记录的显示拼写。完整标签路径最多 256 个 UTF-16 单元、16 级；正文遇到无效或超出保护范围的层级保留最长有效前缀，手动输入则提示完整格式要求。
- Room 升级到 v6，新增全局 `tags`、`note_tags` 和默认值为 0 的 `tag_index_version`；当前解析规则版本为 1。迁移不清空预览或正文，不在迁移中读取文件。
- `MarkdownIndexWriter` 通过 DAO 事务一起替换正文、直接引用和解析版本。父级不生成伪造的直接引用；高于当前规则版本的索引禁止被旧代码覆盖。
- `TagRepository` 用一次引用元数据查询生成树，按 URI 集合计算父级并集，不加载全部正文、不逐节点查询。标签分页查询采用完整路径相等或显式 `/` 边界匹配，避免 `_` 被当成通配符；结果按修改时间和 URI 稳定排序。
- 侧边栏增加笔记库、标签、添加三个入口；只持久化视图选择。支持手动添加、同名复用以及释放没有笔记引用的手动空标签，保留其子标签。独立标签页展示完整路径、数量、所属库及分页卡片；打开笔记使用其所属库上下文。
- 编辑器标签按钮通过普通选区替换插入半角 `#`，保持输入焦点，支持一步撤销与原有草稿保存流程。
- `TagBackfillCoordinator` 持有后台状态与重试任务，分批查询待处理 URI，并逐篇获取和释放 `FileIndexer` 锁。浮层为普通 Compose `Surface`，不遮罩、不获取窗口焦点；成功、失败及并发保存或同步修复均按数据库剩余状态更新。
- 文件读取异常向上传播，与成功读取空文件区分。外部同步所有新增记录成功后才清理消失的 URI；读取失败保留已有索引。启动时授权暂不可用的库也保留索引，可重新选择同一目录恢复权限；用户主动移除库仍清理其笔记引用。
- 应用内 SAF 重命名在同一索引锁内获取已保存快照，并在单个数据库事务中切换 URI、正文、直接引用与原规则版本。同 URI 也支持；事务失败保留原索引并返回实际新 URI，编辑器切换新 URI、保留草稿并提示同步所属库修复。

自动补全、正文标签高亮或跳转、卡片标签 Chip 等后置范围维持原设计。
