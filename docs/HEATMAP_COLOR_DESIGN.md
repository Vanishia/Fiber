# 热力图着色设计

更新日期：2026-11-22。

状态：设计方案，尚未实施。本文只约定热力图的着色方式及必要的数据边界，不代表相关代码已经修改。

## 1. 目标与已确认方向

热力图首先帮助用户一眼看出：**这段时间哪些天记录少，哪些天记录多，以及记录是否连续。**

已确认的方向：

- 侧边栏、最近一年、指定年份和单月视图，各自根据自己的统计范围计算颜色阈值。
- 同样 5 条笔记，在不同月份或不同视图里可以显示不同深浅。这是相对分布的结果，符合本次设计目标。
- 不再要求所有视图共用一套阈值，也不为了跨视图比较而牺牲单个视图的层次。
- 使用有记录日期的数量分布确定分档，不再按单日最大值等宽切分。
- 0 条始终显示为无记录的灰格；同一视图内，相同条数始终同色。
- 复用现有笔记索引、日期归属规则、主题色和网格布局。

本文中的最少样本数、重复阈值处理和颜色映射，是为便于实现而给出的建议默认值；它们尚未经过实机视觉验收。

## 2. 现状与问题

当前 `NoteHeatmapAggregator.colorLevel(count, maxCount)` 的主要逻辑是：

1. 用最大日计数决定启用三档还是四档；最大值达到 20 时启用四档。
2. 将最大值封顶到 32。
3. 根据 `count / cap` 的比例乘以档数，向下取整，再限制为至少第一档。

例如最大值达到 32 时，实际区间为：

| 日计数 | 当前色阶 |
| --- | --- |
| 0 | 无记录 |
| 1～15 | 第 1 档 |
| 16～23 | 第 2 档 |
| 24～31 | 第 3 档 |
| 32 及以上 | 第 4 档 |

因此，平时 1～8 条的日子可能几乎没有区别，少数高产日占据了主要的颜色变化空间。

另外，侧边栏虽然只显示 14 周，当前 `maxCount` 却取自全部历史日期。很久以前的高产日也会影响现在的颜色。统计页已经按筛选条件分别计算最大值，但仍采用上述比例分档。

新方案让颜色跟随当前范围内的日计数分布，减少高产日数值大小对普通日期的压缩。

## 3. 统计范围与数据口径

### 3.1 每个视图独立取样

| 视图 | 参与着色计算的日期范围 |
| --- | --- |
| 侧边栏 | 当前 14 周网格首列的周一至今天，包含首尾 |
| 最近一年 | 今天往前 364 天至今天，共 365 个自然日 |
| 指定年份 | 该年 1 月 1 日至该年 12 月 31 日；当前年只到今天 |
| 指定月份 | 该月 1 日至月末；当前月只到今天 |

补充约束：

- 未来年份或月份的有效范围为空，保留已有空态和占位表现。
- 未来日期、月外占位、年外占位，以及最近一年为对齐星期而补出的范围外日期，都不参与取样，也不显示为有记录的格子。
- 最近一年首周多出的日期应作为范围外占位处理，避免格子显示了一条记录，却不属于本视图的统计范围。
- “当前视图范围”指整个选定时间范围，不是屏幕上正好露出的部分。横向滚动不能改变颜色。
- 每个视图只使用自身范围的样本，不额外借用最近一年或其他月份的数据。
- 保持全部已添加笔记库的统计口径，切换当前笔记库不改变热力图。

### 3.2 不改变笔记归属日期

沿用 `NoteHeatmapAggregator.effectiveDate()` 和 `countByDate()`：

- 文件名符合快速笔记时间戳格式时，归入文件名对应的创建日期。
- 其他笔记按本地时区下的最后修改日期归属。
- 每条笔记只计入一个日期。

这里反映的是当前笔记索引的按日分布，并不是每天发生过多少次写作或编辑操作。修改非时间戳文件的最后修改日期，可能使它从一个日期移到另一个日期；本次不改变这一行为。

## 4. 分位数分档算法

### 4.1 准备样本

从当前有效日期范围内，取所有 `count > 0` 的日计数，按升序排列得到 `S`，样本数记为 `n`。

例如 11 个有记录的日期：

```text
S = [1, 1, 1, 2, 2, 3, 4, 6, 8, 15, 40]
```

这里的 `n` 是有记录的天数，不是笔记总数。每一天权重相同。

不能先把日计数去重再求分位数。上面的三个 `1` 代表三个日期，都要参与分布计算。0 条日期不进入样本，但继续以灰格展示，因此记录是否连续仍然可见。

### 4.2 空数据、少量数据与相同计数

建议首版采用 `MIN_ACTIVE_DAYS = 8`：四档在理想情况下每档至少有两个日期，避免两三个样本就铺满深浅色。

| 情况 | 处理方式 |
| --- | --- |
| `n = 0` | 没有正数色阶，只显示无记录灰格和必要占位 |
| `1 <= n < 8` | 所有有记录日期统一使用第 2 色阶，即中浅色 |
| 全部有记录日期的计数相同 | 统一使用第 2 色阶，不因为日计数大就整片变成最深色 |
| `n >= 8` 且至少存在两种计数 | 进入分位数分档 |

少量样本下暂不展示数量差异是明确的取舍；例如只有两天分别记录 1 条和 20 条时，两天都用中浅色。用户仍可沿用现有点击行为查看笔记。样本达到 8 天后开始展示相对层次，届时颜色可以整体变化。

8 天是可在视觉验收后调整的单一常量，不做成用户设置，也不额外训练或保存个人模型。

### 4.3 计算三个候选分界值

采用最近秩法，不做插值。对 `p = 0.25、0.50、0.75`：

```text
Q(p) = S[ceil(n × p) - 1]
```

上式数组下标从 0 开始。例如前述 11 天的样本得到：

```text
Q25 = 1
Q50 = 3
Q75 = 8
```

最终四档为 `1`、`2～3`、`4～8`、`9 及以上`。

这里不保证每档恰好占 25% 的日期；重复计数不能为了凑比例被拆成不同颜色。

### 4.4 合并重复值，消除空档

按以下顺序处理候选分界值：

1. 按数值去重并升序排列。
2. 删除等于样本最大值的分界值，否则会制造“高于最大值”的空档。
3. 如果仍有分界值，直接使用，不为了凑满四档而补值。
4. 如果没有分界值，但样本确实存在不同计数，取“严格小于最大值的最大实际计数”作为唯一分界，形成两档。

第 4 条专门处理高计数占绝大多数的情况。例如 `[1, 2, 2, 2, 2, 2, 2, 2]` 的三个分位数都是 2；删除最大值后没有分界，因此退回用实际存在的 1 分成两档。这样既保留真实差异，也不创造额外的档位。

最终分界值必须严格递增，且小于样本最大值。每个有效档位至少包含一个真实的有记录日期。

### 4.5 边界归属与颜色映射

分界值是每一档的包含式上界。若分界为 `[1, 3, 8]`：

```text
count <= 0   -> 无记录
count <= 1   -> 第一个有效档
count <= 3   -> 第二个有效档
count <= 8   -> 第三个有效档
count > 8    -> 最后一个有效档
```

将有效档映射到现有四种正数色阶，建议约定为：

| 有效档数 | 从少到多使用的色阶 | 主题色透明度 |
| --- | --- | --- |
| 1，包括少样本和相同计数回退 | `[2]` | `[0.45]` |
| 2 | `[1, 4]` | `[0.25, 1.00]` |
| 3 | `[1, 3, 4]` | `[0.25, 0.70, 1.00]` |
| 4 | `[1, 2, 3, 4]` | `[0.25, 0.45, 0.70, 1.00]` |

有效档位少时拉开已有颜色间的距离，不新增主题色，也不要求使用全部色阶。三档时选择第 3 色阶作为中间色，以接近浅、深两端之间的透明度中点。

同一视图内必须满足：

- 相同计数返回相同色阶。
- 计数增加时，色阶不下降；不同计数允许落在同一档。
- 0 条不能因为分位数回退而带上主题色。
- 每个日期的色阶只取决于本次范围的颜色刻度及该日期计数，不取决于日期顺序。

不再使用“达到 20 条才启用最深色”或“32 条封顶”的绝对限制。足够多样本下，某个月的 2 条也可以是最深色，它表示在该月相对较多。

### 4.6 算法流程伪代码

```text
buildScale(activeDayCounts):
    S = sort(activeDayCounts where count > 0)
    if S is empty:
        return Empty
    if size(S) < 8 or first(S) == last(S):
        return Uniform(level = 2)

    cuts = distinct([Q25(S), Q50(S), Q75(S)])
    cuts = sort(cuts where value < last(S))
    if cuts is empty:
        cuts = [largest value in S strictly below last(S)]

    levels = paletteForBandCount(size(cuts) + 1)
    return Quantile(cuts, levels)

levelFor(scale, count):
    if count <= 0 or scale is Empty:
        return 0
    if scale is Uniform:
        return 2
    bandIndex = number of cuts strictly smaller than count
    return scale.levels[bandIndex]
```

`Empty` 只适用于没有有记录日期的当前范围。颜色刻度和格子必须来自同一数据快照，不能把新格子交给上一次的空刻度。

## 5. 具体效果示例

以下输入均为一个视图内的有记录日计数；0 条日期省略，不影响分界。

| 场景 | 有记录日计数 | 最终分界 | 映射结果 |
| --- | --- | --- | --- |
| 平时少量，偶尔高产 | `1,1,1,2,2,3,4,6,8,15,40` | `[1,3,8]` | `1 → 色阶1；2～3 → 2；4～8 → 3；9+ → 4` |
| 单个高产日数值扩大 | 将上行的 `40` 换成 `4000` | `[1,3,8]` | 所有日期的色阶不变 |
| 重复值合并为三档 | `1,1,1,1,2,2,3,4` | `[1,2]` | `1 → 色阶1；2 → 3；3+ → 4` |
| 大多数日子只有一条 | `1,1,1,1,1,1,1,8` | `[1]` | `1 → 色阶1；2+ → 4` |
| 大多数日子都是高计数 | `1,2,2,2,2,2,2,2` | `[1]`，启用无分界回退 | `1 → 色阶1；2+ → 4` |
| 日计数完全相同 | 八个 `3` | 无 | 全部色阶2 |
| 样本不足 | `1,2,20` | 无 | 全部色阶2 |
| 没有记录 | 空样本 | 无 | 有效日期全部灰格 |

分位数并不保证异常日完全不影响分档：异常日数量增加、占比变化时，分布也会改变。它主要避免单个最大值从 40 变成 4000，就把普通日期的颜色整体压浅。

不同月份也可以产生不同结果：

| 月份样本 | 最终分界 | 同样 5 条的色阶 |
| --- | --- | --- |
| `1,1,2,2,3,4,5,6` | `[1,2,4]` | 4 |
| `1,3,5,8,10,15,20,30` | `[3,8,15]` | 2 |

用户在这里看的是各个月份自己的记录节奏，不承担跨月比较颜色绝对值的成本。

## 6. 界面表现与重算时机

### 6.1 保留现有视觉结构

- 使用现有 `primary` 主题色及四档透明度；无记录格继续沿用各视图已有的 `surfaceVariant` 表现。
- 网格尺寸、圆角、星期排列、滚动和点击行为保持原有约定。
- 月历日期数字继续根据最终色阶选择现有浅底或深底文字色，不能根据有效档位序号误判文字对比度。
- 不增加阈值设置、算法选择器或说明弹窗。
- 若展示色阶图例，使用本次有效色阶，含义为“少 → 多”，不把某种颜色永久标成固定条数。

统计详情页现有解释文案的末句建议改为：

> 颜色深浅按当前时间范围内的记录分布计算，越深表示相对记录越多；有记录天数不足 8 天或每天条数相同时，统一显示中浅色。

保留前半段关于笔记归属日期的说明。不要求侧边栏额外塞入解释文字。

### 6.2 重算条件

以下事件应更新当前视图的颜色刻度：

- 切换最近一年、年份或月份。
- 新增、删除、修改或同步使当前范围内的日计数发生变化。
- 今天的日期或本地时区改变，导致范围或日期归属变化。

边界与稳定性要求：

- 数据相同、日期范围相同，反复进入得到同样的颜色。
- 范围外历史数据的变动可以触发 Flow，但不能影响当前视图的分档结果。
- 普通重组、滚动或同一天内重新打开侧边栏，不改变分档结果。
- 范围、网格和颜色刻度在后台计算后，作为同一个不可变 `UiState` 一次发布，不能短暂混用新网格和旧阈值。
- 保留当前计算期间继续显示旧结果的行为，不先清成灰格再逐格着色。
- 页面前台跨过本地午夜，以及从后台恢复时，需要重新检查今天和时区；无需后台定时任务或额外权限。

样本变化可能使没有改动的日期变色，这是相对分档的自然结果。本版不引入阈值冻结、历史阈值缓存或平滑滞后，否则会增加跨会话状态，也会使当前颜色不再对应当前数据。

## 7. 技术落点

### 7.1 颜色刻度作为纯领域对象

建议新增 `domain/heatmap/HeatmapColorScale.kt`，提供不可变颜色刻度及纯函数：

```kotlin
fun buildHeatmapColorScale(activeDayCounts: List<Int>): HeatmapColorScale
fun HeatmapColorScale.levelFor(count: Int): Int
```

`HeatmapColorScale` 应能表达空数据、统一色阶和分位数三种状态；分位数状态至少保存分界值与对应色阶。构造时保证分界严格递增、`levels.size == cuts.size + 1`，且色阶位于 `1..4` 并递增。

日期范围过滤由聚合或状态构建层先完成，刻度算法只处理日计数，不访问数据库、文件系统或 Compose。

### 7.2 ViewModel 负责范围与一致状态

建议在两个 ViewModel 的状态构建过程中：

1. 从已有 `observeHeatmapEntries()` 获取同一批索引数据。
2. 使用同一个 `today` 和 `ZoneId` 快照聚合日计数、确定有效日期范围。
3. 从该范围提取有记录日计数，生成本视图的颜色刻度。
4. 构建网格，正确标识范围外和未来占位。
5. 一次发布包含范围、网格和 `colorScale` 的状态。

将 `HeatmapUiState` 和 `HeatmapPageUiState` 中用于热力图着色的 `maxCount` 替换为 `colorScale`。视图组件统一调用 `colorScale.levelFor(day.count)`，不各自重算分位数。

本次只替换热力图格子的着色依据；统计页其他条形图等组件用于自身归一化的局部最大值，不属于此次替换范围。

### 7.3 现有文件与建议修改范围

| 文件，相对 `app/src/main/java/com/bird/fiber/` | 职责 |
| --- | --- |
| `domain/heatmap/NoteHeatmapAggregator.kt` | 保留日期归属和日聚合，移除旧比例着色规则；支持有效范围与占位一致 |
| `domain/heatmap/HeatmapColorScale.kt`，建议新增 | 封装分位数、回退和色阶映射 |
| `ui/screens/sidebar/heatmap/HeatmapViewModel.kt` | 按侧栏 14 周有效范围建立刻度 |
| `ui/screens/heatmap/HeatmapPageViewModel.kt` | 按最近一年、指定年、指定月分别建立刻度 |
| `ui/screens/sidebar/heatmap/NoteHeatmap.kt` | 将旧 `maxCount` 着色调用替换为颜色刻度 |
| `ui/screens/heatmap/HeatmapScreen.kt` | 周网格和月历使用颜色刻度，更新解释文案 |

两处现有 `LEVEL_ALPHAS` 可抽成热力图专用的共享 UI 常量，确保侧栏和详情使用同一套调色板。不要因此更改复用这些透明度的其他统计组件的实际外观。

### 7.4 数据与开销

- 不新增数据库字段、迁移或持久化统计表。
- 不读取笔记正文，不追加文件扫描，不保存个人分位数模型。
- 沿用现有 Room Flow，后台计算范围过滤和分档。
- 范围内最多约 366 个日期；刻度构建为 `O(n log n)`，每个格子的档位查询最多比较三个分界值。
- “自适应个人习惯”通过当前范围的实际分布自然实现，无需后台学习过程。

## 8. 验收与测试

### 8.1 算法单元测试

- 第 5 节所有案例均转成固定输入输出测试。
- 无记录返回色阶 0；无记录日期不增加分位数样本数。
- 活跃天数 7 和 8 的切换符合少样本约定。
- 全部计数相同，包括大量同计数样本，始终统一为色阶 2。
- 重复分位数合并、最大值分界删除、无可用分界回退都符合第 4 节。
- 恰好等于分界值时归入下方档位；大于最后一个分界时归入最高有效档。
- 输入顺序不影响结果；相同计数始终同色；计数升高时色阶不下降。
- 空输入和非正计数安全处理，不出现数组越界。

### 8.2 范围与状态测试

- 侧栏不受 14 周范围以外的历史高产日影响。
- 最近一年严格限制在 365 个自然日，首周额外日期不取样、不显示有记录格。
- 年视图排除年外日期，月视图排除月外日期，两者均排除未来日期。
- 不同月份独立分档，同样条数允许不同色阶。
- 相同有效日期与相同日计数生成同样刻度，不因入口不同而变化。
- 修改当前范围内数据后更新刻度；只修改范围外数据时刻度值不变。
- 本地午夜、跨年、闰年二月、时区改变和前后台恢复使用一致的日期快照。
- 页面状态同时带上新范围、新网格和新刻度，不能出现混合状态。

保留 `NoteHeatmapAggregatorTest` 中已有日期解析、按日聚合、周网格、年网格和月网格测试，仅替换旧着色规则的断言，并补充范围边界用例。为新刻度增加独立单元测试，在 `HeatmapPageViewModelTest` 中补充筛选范围与状态一致性测试。

### 8.3 实机视觉验收

- 日常少量记录的月份能看出合理层次，不再因单个高产日全部过浅。
- 0 条灰格和最浅有记录格，在浅色、深色主题中均可区分。
- 单日和少量记录不孤零零地显示成最深色。
- 大量相同计数保持同色，不强行产生花纹。
- 切换月份后的颜色变化可接受，滚动和普通重组不导致变色或闪烁。
